## Setting songs from raw-scores images

- Inspect the actual photos in `raw-scores/` visually, including continuation pages. Rotate/crop enlarged inspection copies into `/tmp` with ImageMagick; keep originals untouched. Read pitches against the staff and key signature, not from memory of the tune. Check flags, dots, accidentals, pickups, rests, slurs and repeat boundaries; add up each bar. Document uncertain readings and editorial corrections in `score.ly` and tell the user.
- Create `scores/<ASCII_title>/score.ly` and `lyrics.yaml` (`title`, `lyrics`, `music`, `strophes: |+`). Use `scores/Aennchen_von_Tharau/` and `scores/Drei_Klaenge/` as worked examples. Preserve `musicOne`, `chordsOne`, `verseOne` and voice `melody` for `LcServer.extractScore`. The current template/editor uses `\fixed c'`, despite the older README saying `\relative`: write octave marks explicitly. Include all photographed strophes and credits.
- Match lyric syllables to notes; use slurs for multi-note syllables and separate lyric lines for repeated music (see Aennchen). Choose readable phrase breaks, including mid-bar breaks where useful. For MIDI use `\unfoldRepeats`, acoustic grand and full written note lengths; do not introduce artificial gaps/staccato or invent accompaniment. Document a chosen BPM when the source gives only a verbal tempo.
- Printed dynamics can sound exaggerated in MIDI. User feedback: Aennchen's playback was usable; Drei Klaenge's printed `p` made the middle too quiet compared with real singing. Treat this as a playback concern to discuss/tune, not proof that the printed marking is wrong. Do not claim a human listening test from MIDI data alone.
- Build just the song with `python3 buildSite.py -f -c <folder>`. For diagnostics run `lilypond --svg -o /tmp/<name>-check scores/<folder>/score.ly` without `-s`; resolve rhythmic/layout warnings. Render `out/<name>.svg` to PNG with Inkscape and inspect it natively against the photo; compilation alone is not verification.
- Test `http://127.0.0.1:4210/<name>.html` through a browser MCP. Chrome DevTools MCP worked here; Playwright MCP lacked its browser. Sandbox curl failing to reach localhost did not mean the browser could not reach it. Inspect `document.querySelector('midi-player').noteSequence.notes` (`pitch`, `startTime`, `endTime`, `velocity`) against an independently transcribed pitch/rhythm list; verify repeats and that gaps match written rests. Click Play and check the complete `note`/`stop` event sequence and elapsed duration. The player omits trailing silence from its displayed duration.
- The server serves song HTML from `out/`: rebuild then reload the browser; no server restart is needed. A single-song build does not rebuild the index/book or copy template assets. Finish with the direct preview URL, chosen tempo and any editorial caveats so the user can judge the sound.
